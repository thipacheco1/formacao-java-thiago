# Ordem de envio ao novo chat

Esta e a sequencia correta para atualizar um novo chat e continuar a formacao Java Backend a partir da aula 388.

Use esta pasta como pacote de contexto:

```text
docs/FONTE_DA_VERDADE_CONTINUIDADE_CURSO
```

## Sequencia obrigatoria

Envie nesta ordem:

1. `ORDEM_DE_ENVIO_AO_CHAT.md`

   Este arquivo. Ele diz ao novo chat em que ordem ler o pacote.

2. `LEIA_PRIMEIRO_FONTE_DA_VERDADE.md`

   Define o estado atual validado: aulas reais de `000` a `387`, M14 em andamento e proxima aula `388`.

3. `PROMPT_MESTRE_CONTINUAR_CURSO_JAVA.md`

   Prompt principal para colar no novo chat. Ele explica o ponto exato de retomada, a aula 388 e as regras que nao podem ser quebradas.

4. `ROTEIRO_OPERACIONAL_RECONSTRUIDO_COMPLETO.md`

   Roteiro macro e operacional do curso inteiro, incluindo o que ja foi feito e o que ainda falta ate o nivel engenheiro/arquiteto.

5. `GRADE_OPERACIONAL_RECONSTRUIDA_COMPLETA_ATUALIZADA_POS_387.csv`

   Grade operacional atualizada. Esta e a CSV correta para continuar agora. Ela marca `000` a `387` como aulas ja geradas e deixa `388` como a proxima aula planejada.

6. `387_M14_32_ASYNC_NO_SPRING_OFICIAL.md`

   Ultima aula real gerada. Ela fecha o assunto de async no Spring e faz a ponte direta para cache com Spring Redis.

7. `REVISAO_EDITORIAL_V2/PADRAO_EDITORIAL_AULA_V2.md`

   Padrao editorial atual: aula principal focada, pratica, estudavel e com material complementar separado.

8. `ANALISE_GRADES_E_ROTEIRO_CONTINUIDADE_POS_259.md`

   Auditoria historica das grades antigas. Use como contexto de decisao, nao como ponto atual de retomada.

```text
Se houver divergencia entre arquivos historicos e os documentos atualizados pos-aula 387,
vence a versao atualizada pos-aula 387.
```

## Mensagem para mandar ao novo chat

Depois de anexar os arquivos, envie:

```text
Leia os arquivos enviados na ordem indicada em ORDEM_DE_ENVIO_AO_CHAT.md.

Use estes arquivos como fonte da verdade para continuar a formacao Java Backend.

Estado atual obrigatorio:
- as aulas reais ja geradas vao de 000 ate 387;
- a ultima aula valida e a 387;
- a aula 387 foi Async no Spring;
- a proxima aula e a 388;
- a aula 388 continua o M14;
- o tema da aula 388 e Cache com Spring Redis;
- nao reescreva aulas antigas;
- nao renumere arquivos;
- nao mude nomes de modulos;
- nao pule assuntos;
- nao avance para rate limiting, upload/download, scheduler, email, testes, Docker de API ou projeto final antes da hora.

Use o Padrao Editorial Aula V2:
- aula principal com foco em aprender, executar, entender e commitar;
- material complementar separado no final;
- sem checklists gigantes na aula principal;
- sem simulado longo em toda aula;
- sem excesso de paragrafos de uma linha;
- sem perder profundidade tecnica.

Antes de gerar a aula, confirme:
1. qual e o ultimo arquivo valido;
2. qual e a proxima aula;
3. qual e o arquivo exato da proxima aula;
4. qual e o tema da proxima aula;
5. quais regras voce nao pode quebrar.

Depois aguarde meu comando GERAR_AULA_388.
```
